# Support panels and official source arrangement

Use support panels for matrix support, advisory groups and shared services shown beside an official hierarchy. Panels contain support roles and people; they are not organizational units and do not create supervisory reporting lines. Each panel identifies the supported organization and retains source evidence, visibility and uncertainty. Assignments can be searched and queried in recorded history.

Canonical JSON imports and reviewed MCP replacements accept `supportPanels` and `sourceLayout`. A panel has an ID, title, kind, `anchorUnitId`, entries and optional `geometry` (`x`, `y`, `width`, `height`) in the same chart coordinates as the organizational cards. An optional `connector` has orthogonal `points` and a solid/dashed style; it is a visual source annotation, not a reporting relationship. Entries retain stable IDs, role, person, assignment status, effective date and provenance fields. Use `needs_review` for uncertainty.

Capture the official slide’s relative positions, sibling order, white space, card bounds and connectors. Place each organizational card at its source position with numeric `style.width`/`style.height` and pin it. Record the source URL, slide/shape locator, capture time and canvas dimensions in `sourceLayout`. Edges may include `data.sourceRoute` with the complete polyline and original `sourceBounds`/`targetBounds`. Source routes are retained while those bounds still match; a deliberate card move uses regular routing. Source geometry is presentation evidence, not authority for an inferred reporting line.

Charts with source layout open in the saved individual-card arrangement. Compact groups remains an optional view and does not overwrite saved positions. Source dimensions/panel bounds are preserved in SVG, PNG, editable PowerPoint, vector PDF and historical versions. A panel without captured geometry is labelled accordingly; the app does not call an automatic position an official source position. Review rendered exports for legibility when copying unusually dense diagrams.

Edit support content through **Edit support panels**. Saves use the current chart version/timestamp and reject concurrent edits. Evidence and visibility are available per assignment. Use JSON for importing complete chart geometry and support panels; accessible CSV adds explicitly labelled support-assignment rows and is a view/table export, not a full database restore format.

**Source comparisons** separately records AI and human comparisons, source URL/revision/locator, findings, scope and timestamp. Fact edits make older comparisons stale; geometry-only edits do not change the compared facts. A hierarchy-only match does not certify omitted support content. Recording an AI check cannot clear human-review questions or mark Current. Normal immutable named versions/checkpoints capture these records too.

MCP exposes **get_source_checks** and **record_source_check** in addition to the existing tools. Both honor pause and selected-chart scope. Read the actual current source separately; recording a comparison never fetches the URL or proves it was checked. The write tool requires expected version and updatedAt, always records an AI actor, and rejects stale saves. New content still follows the normal reviewed proposal flow.

Full schema-v6 backups retain current/historical support panels, source layouts and comparison records; restore merges copies and remaps existing chart-history links. Schemas 1–5 remain accepted. New comparison records cannot be forged or erased through ordinary chart saves/proposals. Normalized new-chart import retains source panels/layout and starts a new Draft; use full backup restore to carry old comparison history. No source coordinates or approvals are inferred for existing charts.

## Captured source drawing

`sourceLayout.presentation` optionally preserves per-card and per-panel drawing primitives, source connector strokes, and standalone source text annotations. It accepts bounded numbers, RGB colors and text runs; it cannot contain SVG markup, scripts or external resources. Text runs can retain source alignment, point size, bold/italic weight, line breaks, color and rotation. Unfilled, unbordered source text frames may overflow their frame as in the original.

Every captured card/panel is bound to its displayed content and size. The source wire/annotation layer also requires matching positions, complete card/panel coverage, and the same relationship IDs, endpoints and classifications. Moving/resizing a card, editing a person/role or panel, changing a relationship, or pinning a route disables stale captured drawing. Recheck the original before recapturing. A source stroke is visual evidence and never establishes supervisory authority. Agent replacements must preserve the complete `sourceLayout` returned by `get_chart` unless the user requested a source-backed presentation correction.

Captured source drawings are used only for internal, individual-card official views and exports. Public exports rebuild from audience-filtered semantic records and omit the captured text/strokes/annotations. Compact and annotated views use their normal drawing. Portable files, versions, checkpoints and undo history retain the safe source metadata. No source font files are stored in a library or shipped with the application.
